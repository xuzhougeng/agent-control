# v0.7.3 版本说明：审批超时可配置

发布日期：2026-05-09
GitHub Release: <https://github.com/xuzhougeng/agent-control/releases/tag/v0.7.3>

> 上游：[v0.7.2](v0.7.2-release-notes.md) · [v0.7.1](v0.7.1-release-notes.md) · [v0.7.0](v0.7.0-release-notes.md)

## 一句话总结

cc-agent 在 `-control-url` 模式下等待运维点 Approve/Reject 的超时时间，**从写死的 5
分钟改成可配置**。三种方式都行：

```bash
# CLI flag
./cc-agent -control-url ws://... -approval-timeout 30s

# Env
CC_AGENT_APPROVAL_TIMEOUT=30m ./cc-agent -control-url ws://...

# JSON config
{ "approval_timeout": "1h" }
```

格式是 Go duration 字符串：`500ms` / `30s` / `5m` / `1h` / `2h30m`...
留空、设 `0` 或乱填字符串都回落到 5 分钟。

## 为什么需要这个

v0.7.1 把 destructive 命令的审批接到 UI，5 分钟写死。两个真实场景下都不合适：

- **运维盯着 chat 在跑** —— 5 分钟太长。模型卡审批 5 分钟才降级到安全方案，
  排错节奏被打断。设 `30s` 更顺。
- **跨时区团队 / 夜班** —— 5 分钟太短。运维睡了 1 小时再回来，所有审批都已超时。
  设 `30m` 或 `1h` 更稳。

## 改动清单（4 个文件，~30 行）

- `cc-agent/internal/transport/control/approver.go`：新增
  `NewRemoteApproverWithTimeout(c, d)` 构造函数；老的 `NewRemoteApprover`
  现在是它的默认 5 分钟包装
- `cc-agent/internal/config/config.go`：`Config` 加 `ApprovalTimeout` 字段
  （Go duration 字符串），新方法 `ApprovalTimeoutDuration()` 解析；env
  `CC_AGENT_APPROVAL_TIMEOUT` 覆盖
- `cc-agent/cmd/cc-agent/main.go`：新 CLI flag `-approval-timeout`，启动时
  `[approval] UI-routed approver: timeout=...` 打印当前生效值
- `cc-agent/internal/config/config_test.go`：3 个测试覆盖默认 / 解析 / 错误回落

## 完全兼容性

- v0.7.3 cc-agent ↔ 任何 v0.7.x cc-control / cc-web / iOS / Win 客户端：✓
- 老命令行不带 `-approval-timeout` 行为完全一致（默认 5 分钟）
- 协议层零改动

## 升级（从 v0.7.2）

```bash
wget -O /usr/local/bin/cc-agent https://github.com/xuzhougeng/agent-control/releases/download/v0.7.3/cc-agent-linux-amd64
chmod +x /usr/local/bin/cc-agent
sudo systemctl restart cc-agent
```

cc-control / cc-proxy / iOS / Win 客户端**没有任何变化**，无需更新。

## 推荐配置

| 场景 | 推荐值 | 备注 |
|---|---|---|
| 开发 / 实测 | `15s` | 模型尝试 destructive 命令时立刻拒绝，迭代快 |
| 实时运维（运维在场） | `30s` ~ `1m` | 给运维一秒"看一眼再决定"的余地 |
| 默认 | `5m` | 兼顾响应性和操作员上下文切换 |
| 夜班 / 异步 | `30m` ~ `1h` | 等运维收到通知再回来点 |
| 跨时区 / 离线审批 | `4h` ~ `8h` | 等下一个班次的人接手 |

> 即将到来的 Approval webhook（Slack/Email）会让超时更宽松——异步推送通知后等下一个运维点击。
