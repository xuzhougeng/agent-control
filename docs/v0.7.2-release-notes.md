# v0.7.2 版本说明：iOS / Windows 审批卡片标记 cc-agent 来源

发布日期：2026-05-09
GitHub Release: <https://github.com/xuzhougeng/agent-control/releases/tag/v0.7.2>

> 上游版本：[v0.7.1](v0.7.1-release-notes.md) ← UI 路由审批闸主体功能，
> [v0.7.0](v0.7.0-release-notes.md) ← cc-agent 模块上线。本版本是 v0.7.1 的小迭代。

## 一句话总结

iOS 与 Windows 客户端的 Pending Approval 卡片现在会显示一个紫色 **`cc-agent`** 徽章，
区分这条审批是来自新 cc-agent 的 destructive 命令拦截（紫色徽章）还是来自旧 cc-proxy 的
PTY 提示（无徽章）。运维一眼能看出审批的来源，决策时心里更清楚。

## 背景

v0.7.1 已经把 cc-agent 的 destructive 命令审批接到了 cc-control，并复用 cc-web
的 Pending Approval 卡片 UI。当时验证发现：

- **iOS / Windows 客户端早就有 Approve/Reject 按钮**（v0.6 给 PTY 提示做的）
- **v0.7.1 的服务端分流（`HandleClientAction` 读 `SessionEvent.AgentRequestID`）让旧按钮直接对 cc-agent 审批生效**——零协议改动

也就是说，**iOS / Windows 装上 v0.7.1 的 cc-control 后，审批按钮已经能用**，
只是用户看不出哪条审批是 cc-agent 来的。v0.7.2 加上视觉区分，不动协议。

## 三端徽章一致

cc-web、iOS、Windows 三端在 cc-agent 审批卡片上都加上紫色 `cc-agent` 徽章：

```
旧 PTY 审批：
┌─────────────────────────┐
│ 8536aa5c @ ops-01       │
│ instance ad4aef30       │
│ y to confirm or n...    │
│ [✓ Approve] [✕ Reject]  │
└─────────────────────────┘

新 cc-agent 审批：
┌─────────────────────────────────┐
│ 8536aa5c [cc-agent] @ ops-01    │  ← 紫色徽章
│ instance ad4aef30               │
│ [recursive rm] rm -rf /var/...  │
│ [✓ Approve] [✕ Reject]          │
└─────────────────────────────────┘
```

## 改动清单（4 个文件，42 行）

### iOS（AgentControlMac）

- `Sources/Shared/Core/Models.swift`：`SessionEvent` 加 `agentRequestID: String?`
  字段 + `isFromCCAgent` 计算属性；WS 事件解析器读 `agent_request_id` 字段
- `Sources/Shared/Views/ApprovalPanelView.swift`：`ApprovalRow` 在
  `event.isFromCCAgent == true` 时渲染一个 `SessionTag(text: "cc-agent",
  tint: WorkspaceTheme.accent)`

### Windows（AgentControlWin）

- `Core/Models.cs`：`SessionEvent` 加 `AgentRequestId` 字段 + `IsFromCCAgent`
  属性；顺手把所有字段补全 `[JsonPropertyName]` 注解保持类内一致风格
- `Core/Models.cs` `ParseSessionEvent`：手工 JsonElement 解析器读
  `agent_request_id`
- `Views/SidebarControl.xaml`：DataTemplate 在 `IsFromCCAgent=true` 时显示一个
  紫色 Border pill (`#6C4AB6` / `BoolToVis` converter)，与 cc-web
  的 `.badge-runtime-agent` 视觉一致

### cc-web（v0.7.1 已加）

- `js/workspace/session.js` + `styles/workspace.css`：紫色 pill on
  `agent_request_id` 非空的审批

## 升级（从 v0.7.1）

```bash
# 拉新二进制
wget -O /usr/local/bin/cc-agent https://github.com/xuzhougeng/agent-control/releases/download/v0.7.2/cc-agent-linux-amd64
wget -O /usr/local/bin/cc-control https://github.com/xuzhougeng/agent-control/releases/download/v0.7.2/cc-control-linux-amd64
chmod +x /usr/local/bin/{cc-agent,cc-control}
sudo systemctl restart cc-control
sudo systemctl restart cc-agent

# iOS / Windows 客户端：从源码重新构建
# (二进制分发还没接到 Apple Notary / Microsoft Signing，要自己 Xcode / VS 编译)
```

cc-control 二进制无功能变化（仅服务 cc-web 静态资源），仍可继续用 v0.7.1。
v0.7.2 主要价值是 native 客户端代码。

## 完全兼容性

- v0.7.2 cc-agent / cc-control / cc-proxy ↔ 任意 v0.7.1 / v0.7.0 / v0.6.x 客户端：✓
- v0.7.2 客户端 ↔ v0.7.1 cc-control：✓（徽章字段服务端已发出）
- v0.7.2 客户端 ↔ v0.6.x cc-control：✓（`agent_request_id` 字段缺失时 `isFromCCAgent` 为 false，徽章不显示）

## 已知 caveat（v0.7.1 时遗留）

- 审批超时仍是 **固定 5 分钟**（roadmap 上要做成 flag）
- 同一 chat session 同一时刻仍只能有一个待审批
- 浏览器对 ES module 缓存激进；升级后做 hard reload (`Ctrl+Shift+R`)
