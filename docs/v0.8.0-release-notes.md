# v0.8.0 版本说明：技能市场（skill marketplace）

发布日期：2026-05-09
GitHub Release: <https://github.com/xuzhougeng/agent-control/releases/tag/v0.8.0>

> 上游：[v0.7.3](v0.7.3-release-notes.md) · [v0.7.2](v0.7.2-release-notes.md) · [v0.7.1](v0.7.1-release-notes.md) · [v0.7.0](v0.7.0-release-notes.md)

## 一句话总结

团队里任何 cc-agent 主机 `:reflect` 出来的 skill，现在可以通过 cc-control 共享给整个 fleet：
`:publish` 推送，`:install` 拉取（带预览 + y/N 确认），cc-web 新增 Skills 标签页用于浏览
和远程下发。技能用 sqlite 持久化、按版本累积，最新版默认胜出，过往版本保留可回滚。

## 启用

cc-control 端加一个 flag（也可以用 `REGISTRY_DB` 环境变量）：

```bash
./cc-control -registry-db /var/lib/cc-control/registry.db
```

flag 不设置时整套功能完全 off：注册表路由不挂载，旧的 cc-agent 行为完全不变。

cc-agent 端只要本来就有 `-control-url` + `-agent-token`，HTTP 基址会自动从 WS URL 推导
出来（`ws://host:18080/ws/agent` → `http://host:18080`）。需要走不同主机/协议时用：

```bash
./cc-agent -config-http-url https://control.example.com
# 或 CC_AGENT_CONTROL_HTTP_URL=https://control.example.com
```

## REPL 新增的 5 条命令

```
:registry [search]               列出团队 skill
:publish <name>                  把本地 skill 推到 cc-control
:install <name>[@version]        拉取 + 预览 + y/N 确认 → 写到 skills_dir/team/
:history <name>                  显示某个 skill 的所有版本
:rollback <name> <version>       安装指定历史版本
```

`:install` 会先把 prompt / tools / 作者 / 时间戳打印出来，操作员看清楚再确认。skills 目录
现在分两层：

- `<skills_dir>/local/<name>.json`：本地 `:reflect` 产出
- `<skills_dir>/team/<name>.json`：从 registry 安装的

加载顺序是 local 在前、team 在后，map 后写覆盖前写，所以同名时 team 总是赢。想退回 local
版本，删掉 `team/<name>.json` 即可。

## cc-web 端：Skills 标签页

新地址：<http://your-control:18080/skills>

左侧搜索 + 列表，右侧详情面板（prompt 全文、工具标签、版本历史、Install on host… 按钮）。
点 Install on host 会让 cc-control 通过 WebSocket 给指定 server_id 的 agent 推一帧
`install_skill_request`：agent 解码后原子写入 `team/<name>.json` 并热加载技能注册表 ——
不需要 agent 重启，操作员也不用再去对应主机上敲 `:install`。

## REST API（cc-control）

| Method | Path | 说明 |
|--------|------|------|
| POST | `/api/registry/skills` | 发布 |
| GET | `/api/registry/skills?q=…` | 列表 |
| GET | `/api/registry/skills/:name[?version=N]` | 取一个，缺省返回最新 |
| GET | `/api/registry/skills/:name/history` | 全部版本 |
| DELETE | `/api/registry/skills/:name/:version` | 软删除（仅 admin） |
| POST | `/api/registry/install_request` | 操作员触发远程安装 |

agent 通过 `Authorization: Bearer <agent-token>` + `X-Server-ID: <server-id>` 鉴权；
操作员通过 cc-web 现有的 UI token。所有错误返回统一 `errBody{code, field, reason}` 形态，
方便客户端 switch 处理。

## 安全/边界

- 路径穿越：skill 名称按 `^[a-z][a-z0-9-]{1,63}$` 校验，HTTP 入口和 WS 入口两道关都拦。
- 版本单调：`MAX(version)+1` 在 sqlite 事务里算；`SetMaxOpenConns(1)` 把写入串行化，
  并发 `:publish` 不会撞版本号。
- 软删除不会回收已经下发到 agent 的文件；若要彻底撤销，要去对应 agent 上手动删除。

## 不在这一刀里的

- 公开 / OSS registry：当前是单组织私有的，签名、跨组织联邦、内容可寻址都留到 v2。
- 订阅 / channel 推送：installs 仍然是操作员触发，没有 agent 自动同步。
- cc-web 端 e2e 测试 harness：因为 v0.7.3 cc-agent 重构后，`tests/web-e2e/run-harness.sh`
  会启动失败（与 skill marketplace 无关），新加的 `tests/web-e2e/specs/skills.spec.js`
  在手动起 cc-control 的环境下能跑通。harness 修复留下次。


## 升级路径

老配置完全向前兼容：

- cc-control 不带 `-registry-db` ⇒ 注册表关闭，行为同 v0.7.3。
- cc-agent 不设 `control_http_url` + `agent_token` ⇒ 5 条新 slash 命令打印
  `(registry not configured)` 并立即返回；REPL 其它行为完全不变。
- skill 文件原来就在 `skills_dir/` 里平铺的，会自动 fallback 走平铺加载，不需要手动迁移。

## 预编译二进制

GitHub Release 页面附 19 个预编译产物（CGO 关、`-trimpath -ldflags "-s -w"`）。
按部署位置分三组：

**控制面（部署在中心服务器，1 个）**

| 文件 | 用途 |
|------|------|
| `cc-control-linux-amd64` | 控制面进程；REST + WebSocket + 注册表（`-registry-db` 启用） |

**Agent（部署在被管 host，6 个平台）**

| 文件 | 平台 |
|------|------|
| `cc-agent-linux-amd64` / `cc-agent-linux-arm64` | Linux |
| `cc-agent-darwin-amd64` / `cc-agent-darwin-arm64` | macOS（Intel / Apple Silicon） |
| `cc-agent-windows-amd64.exe` / `cc-agent-windows-arm64.exe` | Windows |

**cc-proxy 辅助二进制（chat 模式协议适配，12 个）**

| 文件族 | 用途 |
|--------|------|
| `cc-chat-claude-<os>-<arch>` | 把 Claude Code CLI 包成 cc-proxy 期望的 chat 协议 |
| `cc-chat-echo-<os>-<arch>` | 测试用 echo bot；运行时不调 LLM，便于 e2e/烟测 |

每族同样 6 个平台（linux/darwin/windows × amd64/arm64）。

**取用方式**

```bash
# 单个文件
curl -LO https://github.com/xuzhougeng/agent-control/releases/download/v0.8.0/cc-agent-linux-amd64
chmod +x cc-agent-linux-amd64

# gh CLI 批量
gh release download v0.8.0 --repo xuzhougeng/agent-control --pattern 'cc-agent-linux-*'
```

注：v0.8.0 是 v0.7.3 之后第一个由 GitHub Actions 全量构建发布的版本（`compile.yml`
工作流修复了 cc-chat-{claude,echo} 的模块路径，从 cc-agent/cmd 迁到 cc-proxy/cmd）。
