# 文档写作规范

本文档约定 `docs/` 与根 README 的 Markdown 写作规则，便于统一风格与后续维护。

## 语言与术语

- **叙述语言**：以中文为主；英文仅用于命令、API 路径/字段、代码标识符、专有名词。
- **术语首次出现**：使用「中文（English）」格式，例如：控制面（Control Plane）、会话（session）、租户（tenant）。同一篇内后续可只用中文或英文其一。

## 标题层级

- 每篇文档仅使用 `#`、`##`、`###` 三级。
- `#` 仅出现一次，作为文档标题。
- 避免四级及以下标题；若内容过多，可拆成多篇或用列表。

## 占位符

- 示例中的占位符统一使用 `<UPPER_SNAKE_CASE>`，例如：`<ADMIN_TOKEN>`、`<CC_CONTROL_URL>`、`<AGENT_TOKEN>`。
- 避免混用 `YOUR_TOKEN`、`your-token`、`<tenant-a-id>` 等风格；若表示具体示例值，可写为「示例：`tenant-a-123`」。

## 命令与代码块

- 每个命令或代码块应尽量**可直接复制运行**；若需先修改再运行，在块前用一句话说明前置条件（如：在仓库根目录、已设置 `AGENT_TOKEN`）。
- 涉及多平台时，按 **Linux → Windows → macOS** 顺序分小节；同一小节内只放当前平台命令。

## 链接

- **仓库内文档**：一律使用相对路径，例如 `[API 参考](api.md)`、`[公网部署](deploy-public-server.md)`、`[后台部署](deploy-public-server/04-agent-background.md)`。
- 指向根 README 的锚点：`[Quick Start](../README.md#quick-start)`。
- 优先使用可点击的 Markdown 链接，避免仅用反引号写出路径。

## 文档类型与结构

- **入口 / README**：概览 + 快速开始 + 到其他文档的索引链接。
- **API 类**：鉴权说明 + 端点与参数 + 请求/响应示例 + 错误约定。
- **操作指南（How-to）**：前置条件 + 分步操作 + 验证方式（必要时加回滚或排错）。

## 维护

- 新增或大改文档时，同步更新 [文档索引](README.md) 与根 [README - Docs](../README.md) 中的链接。
- 单篇内避免大段复制其他文档内容；用「详见 [某文档](链接)」引用，保持单一事实来源。
